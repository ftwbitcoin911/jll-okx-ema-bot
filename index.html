JLL · 全自动交易系统部署流程

从 0 到 1 跑通 OKX EMA 策略机器人

A
阶段一：环境准备与服务器部署
  • 1
    购买服务器：推荐腾讯云轻量服务器，节点选新加坡或东京（切勿选大陆/香港）。
  • 2
    安装面板：镜像选择 宝塔 Linux 面板，登录宝塔完成初始化。
  • 3
    上传代码：在宝塔【文件】中新建目录 /www/okx_bot，上传 4 个文件：
    okx_1k_bot.py btc.json eth.json requirements.txt
  • 4
    安装依赖：打开宝塔终端，执行以下命令：
    cd /www/okx_bot
    pip3 install -r requirements.txt
B
阶段二：修改 JSON 配置（修正 8H 致命错误）
🚨 严重警告：OKX 根本没有 8 小时 K 线！ 您原有的 "bar": "8H" 是非法配置。只要保留 8H，程序一启动就会报错退出（错误码 51000），绝对不会开单！OKX 仅支持：1m 5m 15m 1H 4H 6H 12H 1D 等。
  • 1
    修改周期与参数：将 "bar" 改为 "1D"（日线），将 "ema_period" 改为 30。
    "inst_id": "BTC-USDT-SWAP",
    "bar": "1D",
    "ema_period": 30
  • 2
    配置 OKX API：去 OKX 官网申请 API Key，权限仅勾选【读取】+【交易】，切勿开提现，绑定服务器公网 IP。
    将三件套填入 JSON：
    "api_key": "你的真实API_KEY",
    "secret_key": "你的真实SECRET_KEY",
    "passphrase": "你的真实密码短语"
  • 3
    配置 Telegram（可选，但强烈建议）：在 Telegram 中创建 Bot，并记录 bot_token 与 chat_id，用于发送下单、交易日志和异常告警。
    "telegram_token": "你的BOT_TOKEN",
    "telegram_chat_id": "你的CHAT_ID"
C
阶段三：手动试跑与日志校验
  • 1
    先试跑，不要直接开实盘：在服务器上执行 python3 okx_1k_bot.py，观察日志是否出现连接成功、订阅成功、读取行情成功等信息。
  • 2
    检查策略判断：确认程序能正确读取 K 线、计算 EMA、输出买卖信号，并且对时间周期和交易品种正确匹配。
  • 3
    排查关键错误：如果你看到 51000、Invalid bar、upstream connect error，优先检查选项、权限、网络、IP 白名单和 JSON 结构。
D
阶段四：后台进程部署
  • 1
    使用守护进程：推荐使用 screen 或 nohup，保证程序不中断地持续运行。
    cd /www/okx_bot
    nohup python3 okx_1k_bot.py > bot.log 2>&1 &
  • 2
    日志文件：通过 tail -f bot.log 实时查看是否有异常、重连、订单下单或撤单记录。
  • 3
    定时检查：每日检查 VPS 负载、磁盘、网络和程序状态，避免脚本在后台失联导致错误累积。
E
阶段五：交易所与 Telegram 联调
  • 1
    绑定 OKX 账户：确认 API 权限正确，IP 白名单与服务器公网 IP 一致；若配置错误，程序会读取失败或拒绝下单。
  • 2
    Telegram 通知：建议每次下单、平仓、异常和重启都通过 Telegram 通知，提升运维可视性。
  • 3
    风控首要：设置最小资金阈值、最大单笔金额、亏损强制停机与人工确认机制，避免系统失控。
F
阶段六：实盘前检查清单
  • 1
    确认配置无误：检查 inst_id、bar、ema_period、API Key、Secret、Passphrase 和 Telegram 配置是否全部正确。
  • 2
    确认资金与仓位：用极小仓位测试程序是否会开单、平仓和发送通知，确保不会在不必要的情况下触发真实交易。
  • 3
    保留人工停止渠道：如果行情异常或程序逻辑偏离预期，必须能在 1–2 分钟内停掉策略，避免长期无监控运行。
